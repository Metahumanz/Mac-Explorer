# 网络驱动器删除：实现与隔离验收

日期：2026-10-20。用户在 4C/权限修复收尾后，明确要求网络驱动器删除对齐 Windows。4C 和权限修复已独立提交 `96c79d5`。本次是追加功能，仍使用隔离原生构建，不安装、不推送、不发布。

## 实现

- 网络挂载上的普通项目使用“删除”入口，始终显示“永久删除”确认，包含数量与最多五个源路径；初始焦点为取消，没有“不再询问”。本地项目保留系统回收站和已有确认偏好。混合选择的确认文案分别列出网络与本地数量。
- 选择/菜单使用内核缓存挂载表，不根据卷名猜测类型。永久删除计划在后台打开父目录，通过 `fstatfs` 确认网络挂载，绑定父目录及条目身份；确认后再次校验挂载、父路径及原条目。无法确认网络类型时不会据此永久删除本地项目。
- 递归使用目录描述符及 `unlinkat`，不跟随符号链接、不跨嵌套卷、不修改权限、不自动重试。挂载根、文件系统根和受保护的系统/用户主目录拒绝作为删除项目。对文件内容不增加读取、哈希、复制或备份。
- 永久删除不产生回收站来源记录或撤销记录；本地回收站仍记录来源并可撤销。仅实际完成的删除消费剪贴板对应路径，不覆盖操作期间被其他应用改写的剪贴板。失败项保留选择及剪贴板。
- 权限/网络错误保留原因、码及实际失败路径。目录中途失败可能已移除部分内容，错误明确提示；不会静默回滚或承诺原子删除。回收站失败不自动降级成永久删除。

## 验收范围

核心检查使用全新本地临时目录及注入的网络分类；AppKit 检查通过实际删除入口、确认/取消按钮和真实本地权限失败验证流程。系统 Trash 用临时模拟目的地替代。没有在真实 NSSD、passport 或其他 NAS 上创建、删除测试文件；没有调用 SSH、改 NAS 权限或创建清理备份。

本轮日志位于忽略提交的 `native/output/validation/network-delete-20261020/`，最终完整 UI 报告及确认框截图归档在该目录的 `smoke-final/`，也位于 `native/output/validation/smoke/`。核心完整 12 组、750 项断言通过；网络删除专项 22 项通过。AppKit 完整 511 项通过、1 项 SVN 工具缺失跳过，其中新增网络删除 UI 20 项通过；常规启动 3 次、重启持久化子检查通过，主夹具内容保持不变。1.1.0 arm64 隔离包严格签名校验通过，两个语言资源与源码相同，本地化 532 个源码字符串通过。日常安装版可执行文件、Info.plist 及偏好设置与先前基线散列一致。网络删除两类临时夹具根在测试后只读核实不存在，见 `fixture-cleanup-readback.json`。最初构建诊断及因源码仍在编辑而中断的核心检查日志保留，不计入通过结果；最终核心日志为 `core-final.log`，修正测试并发捕获警告后的专项日志为 `core-targeted-final.log`。

## 剩余限制

- 本轮验证网络路由/确认逻辑和本地 POSIX 删除行为，不等于已通过真实 SMB 永久删除验收；断连、服务器 veto/ACL、NTFS 伴随文件策略及服务端回收站仍以实机结果为准。此改动不会绕过之前导致残留的共享拒绝访问。
- 真实 SMB 只在另行确认具体新建小夹具后验收，不操作既有真实文件。既定 Phase 0–4C 已完成，没有默认开启下一功能阶段；其他未覆盖硬件/服务端场景保留在开发计划中。
- 删除检查与系统调用之间存在并发窗口，网络调用也可能阻塞；描述符/身份检查降低路径替换风险，不构成事务、崩溃恢复或零竞争保证。已确认目录的后代按执行时枚举；中途失败不恢复已删除内容。
- Windows 参考依据与文件夹重定向例外见 [行为基准](WINDOWS_FILE_OPERATION_BASELINE.md#用户追加网络驱动器删除)。不推断所有 Windows 网络位置都没有回收站，也不承诺或管理 NAS 服务端的回收/快照。
