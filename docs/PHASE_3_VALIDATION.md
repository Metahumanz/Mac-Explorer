# Phase 3：网络卷分类与容量显示

日期：2026-10-20。用户授权开始 Phase 3，基于 Phase 2 提交 `94b79b7`，沿用 `feat/metadata-safe-file-operations` 分支。实现、检查及文档已纳入 Phase 3 本地提交；未推送或安装。Phase 4 建议安排已整理，尚未授权开发。

## 实现及行为

- `NativeVolume.kind` 明确区分本地、网络和未知；不再将缺失的本地标记视为 `true`。优先使用内核挂载快照的 `MNT_LOCAL`，没有该挂载证据时回退到 URL 的可选本地标记，两者均缺失才为未知。使用 `getmntinfo_r_np` 的私有缓冲区并释放，避免地址建议和磁盘卡片并发读取共享静态缓冲区；不按卷名猜类型，也不读取挂载来源账号/地址。
- 卷枚举失败抛出简短错误；单卷属性读取失败保留其挂载位置和已知类型，容量标为不可用，不无声丢弃该卷。挂载快照读取失败时仍可使用 URL 类型证据。
- 总容量和可用容量保留可选值，区分完整、部分缺失、全部未知、非法组合和读取失败。负数不转为零，`free > total` 不用于绘制占用比例；真实 `0 / 0` 仍显示零容量。只有可信的正总容量及已知可用值才显示原有占用条，其他状态不画空盘比例。
- 卡片显示“本地磁盘 / 网络驱动器 / 类型未知”；容量显示已知值、未知或不可用，保留现有卡片尺寸、名称、图标来源、打开和推出入口，并补充无障碍标签。根卷禁止推出及既有推出目标校验保持不变。
- 网络页只列已确认的网络卷，已知网络类型但容量读取失败的卷仍可见。未知类型仍在“此电脑”可访问，不擅自当作网络卷。枚举失败状态与 Bonjour 发现状态分开显示；“重新查找”同步刷新挂载列表，失败恢复后清除错误。请求序号及页面版本防止较慢的旧结果覆盖新页面或刷新结果。
- `ExplorerAddressBar` 仍通过同一卷列表读取名称和 URL；未知/单卷失败的卷保留建议目标，整体失败沿用已有错误反馈。Phase 1 文件传输及 Phase 2 排序核心源码与 `94b79b7` 相同。

## 边界与后续

- 隔离包已由自动脚本退出，未替换日常 1.1.0 应用、未修改系统默认项。真实推出、真实断连、写满或重新挂载没有执行；这些状态通过注入检查覆盖。
