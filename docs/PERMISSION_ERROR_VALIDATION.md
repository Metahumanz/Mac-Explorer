# 权限错误提示修复与计划收尾核对

日期：2026-10-20。用户在 4C 体验中发现旧 SMB 测试残留无法删除，应用反复提示“前往设置”，随后授权修复并询问计划是否完成。

## 修复范围

- 新增 `NativeFileFailure`，有界解析 NSError 及其 underlying error，保留实际失败路径、权限错误域/代码，识别 Cocoa、POSIX EACCES/EPERM 及 OSStatus 权限错误。非 Cocoa 域的相同数字不再误判成文件不存在。
- 网络位置从系统缓存挂载表按最长路径边界匹配，不按共享名称或 `/Volumes` 前缀猜类型，不读取服务器配置或发起网络元数据请求。共享错误提示检查共享权限/服务器限制，不显示“前往设置”；无法分类时不推断是 macOS 隐私授权问题。
- 本地权限错误同时提示文件权限与应用访问授权，系统设置仅作为可选入口，不再把 EACCES/EPERM 当作确认缺少完全磁盘访问权限的证据。后续错误、关闭提示和导航不能沿用旧的权限恢复状态。
- 读目录、搜索、单项创建/重命名及回收站错误使用操作发生时的位置或具体来源，避免连接/导航后的当前目录影响错误分类。失败路径优先采用底层错误提供的实际子项。
- 删除全部失败时保留原选择、剪贴板和源项目；仍只走既有系统回收站流程，未增加自动永久删除、重试、ACL 改写或服务器权限绕过。回收站服务注入仅用于本地故障验收。
