# Phase 1：Windows 文件资源管理器行为基准

2026-10-20 用户要求：Phase 0.5 单独提交；Phase 1 中此前列出的行为取舍全部参考 Windows 文件资源管理器。Phase 0.5 已提交为 `511f6af`，不含文件操作改动。本文取代此前自定义的“多轮哈希、隐藏来源、阶段日志、默认人工恢复”方案。

## 依据及证据边界

以 Windows Shell 的操作接口、文件时间和错误处理文档作为实现参考，区分官方接口契约、项目在 macOS 上的对应实现，以及尚待 Windows 11 实机比较的细节。没有 Windows 实机对照证据时，不声称复刻了 Explorer 的所有内部算法、默认按钮或每种文件系统的日期规则。

- [Shell 操作选项](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)：错误交互、逐项跳过、同名改名、撤销，以及跨卷目标权限继承的选项。
- [Shell 逐项进度通知](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ifileoperationprogresssink)：以实际操作进度和每项结果通知调用者。
- [CopyFileEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-copyfileexw)：系统复制、流与属性处理、取消及未完成副本的处理。它描述 Win32 接口，不足以证明 Explorer 每个分支的实现。
- [复制进度与取消回调](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nc-winbase-lpprogress_routine)：完成字节数、继续、取消及停止的区别。
- [跨卷移动接口](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefilewithprogressw)：移动与进度、跨卷复制及清理行为。
- [文件时间](https://learn.microsoft.com/en-us/windows/win32/sysinfo/file-times)：文件系统支持和精度不同；NTFS 时间表示及 FAT 创建/修改时间精度不同。
- [SMB2 时间字段](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d166aa9e-0b53-410e-b35e-3933d8131927) 和 [文件时间编码](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/a69cc039-d288-4673-9598-772b6083f8bf)：使用 FILETIME 的 100 ns 表示；协议单位不代表服务器底层精度或日期持久保存能力。

“无额外应用层哈希”是按系统复制工作流作出的实现选择，不是从文档缺少哈希参数就推断 Windows 内部绝不校验。NTFS ACL 与 macOS 权限模型不能逐字段照搬；保留系统实现和目标继承语义，不把哈希一致视为全部属性等价。

## 原 11 项审核行为的处理

| 原审核项 | 本轮对应行为 | 实现/限制 |
| --- | --- | --- |
| 1. 多轮哈希 | 使用系统复制结果与进度，不默认额外读取全部内容 | 已删除应用层 SHA-256 及扩展属性摘要。保留清单、大小、类型、链接及身份/日期检查；不声称进行了内容校验和验证 |
| 2. 普通复制范围 | 同卷移动仍是排他改名；复制走系统复制，不附加校验模式 | 本地、跨卷、同目录副本的入口一致；没有自定义“严格哈希”设置 |
| 3. 日期失败 | 提示重试、仍然复制/移动、跳过、取消 | 只有明确选择仍然继续才接受属性损失；完成结果保留警告。无交互调用默认跳过，原始日期保留目标仍优先 |
| 4. 日期精度 | 按已知文件系统表示能力比较，不要求所有卷支持 APFS 纳秒 | 本地保持实际精度；SMB/NTFS 按 100 ns 表示，FAT 按文档精度。其他未知情况不猜容差，交给属性损失选择；真实 NAS 能力尚未验收 |
| 5. 来源隐藏改名 | 来源保持原名称，复制完成前不删除 | 已删除 `.mac-explorer-source-*` 及相关重试消费逻辑；清理失败时剩余项保留原位置 |
| 6. 异常副本 | 取消/失败先清理本次私有暂存副本，重试从干净状态开始 | 不日常保留完整失败副本；清理失败或目录身份变化时才保留并显示路径。阶段 JSON 和额外 fsync 已删除 |
| 7. 恢复操作 | 当前操作内提供进度、取消及错误选择 | 正常错误不要求用户找隐藏日志。真正无法清理的残留仍需按路径核对；没有跨进程自动恢复或断点续传 |
| 8. 剪贴板/撤销 | 只消费完成移动；失败项和未执行项保留 | 不再因为失败来源被隐藏改名而消费剪切项。部分目录清理仍可能发生，不能误报为已完成移动 |
| 9. 冲突/重试 | 重试、保留两者、跳过、取消；在当前操作内重试清理 | 继续遵守仓库“不覆盖碰撞目标”约束，不提供替换现有目标。不会把重试自动变为覆盖或内容合并；部分目录失败后的新操作仍可能遇到同名 |
| 10. 撤销/还原 | 共用系统复制、日期恢复及错误选择，不附加哈希 | 完成与警告分开判断，已完成但带警告的还原也清理对应来源记录；保留身份和碰撞保护 |
| 11. 其他属性 | 系统复制负责原生扩展属性和资源分支，属性复制失败需交互 | 原先 16 MiB 扩展属性/约 4 GiB 资源分支的应用层上限已删除；不强制源 ACL 等价，沿用目标原生继承能力 |

主界面布局和现有功能保留。进度窗口延迟 300 ms 显示，避免快速移动闪窗；显示当前项目的实际复制字节进度。复制期间可取消，错误对话框选择作用于当前操作。没有宣称新增完整 Windows 传输队列、暂停恢复、应用到全部项目、目录合并或跨应用会话撤销。

## 日期目标和安全要求

用户最初要求跨 SMB/NTFS 剪切尽量保留原创建、修改日期，继续作为本项目验收要求。不能把 Windows 的新文件创建规则、某个 API 或其他文件系统的结果直接套用为用户 Samba/NTFS 的实测结论。

- 仍按目录后序恢复创建/修改日期，重新读回比较；来源变化或目标身份异常时不继续删源。
- 用户选择“仍然移动”时，界面明确说明继续会移除来源且可能丢失部分属性；不得静默降级。
- 复制数据依赖系统复制的成功结果，不额外计算哈希，因此不能再宣称能检测“系统报告成功且大小/元数据未变的同长度数据损坏”。
- 链接只操作自身，特殊节点、树内其他设备节点和过深层级保留安全拒绝。取消不能回滚已完成的批次项目；清理阶段可部分完成。
- 清单仍占用内存，准备/元数据检查仍会产生目录与 stat 请求；“无额外全量读取”不等于“零额外 I/O”。系统调用阻塞时，取消也可能需要等待系统返回。

## 验收与剩余差异

本轮检查覆盖系统复制实际字节、原始日期、链接、硬链接内容、资源分支、属性失败选择、单次提示、重试、保留两者、取消、来源/目标替换、清理失败及残留路径。自动回归中已有批次冲突选择 Skip；新增 AppKit 检查实际打开属性丢失对话框、操作 Skip 和取消按钮。

仍需真实 Windows 11 与 macOS/SMB 小夹具对照：普通复制和跨卷移动的创建日期、目录日期、权限继承、不同精度卷、网络断连和磁盘写满。Windows 参考行为不能证明内部实现相同；本项目继续以用户要求的原创建/修改日期保留为验收目标，不宣称 Windows 全量行为一致。

后续用户已授权真实 SMB 小夹具测试和兼容修复、重新验收。[首次失败](SMB_VALIDATION.md)保留为历史，最新源码、结果及限制见 [SMB 专项复验](SMB_PHASE1_REACCEPTANCE.md)。SMB 不支持排他改名时，同共享移动会回退为一次安全复制再删源；不能把此路径的性能表述成 Windows 服务端原地改名，也不要求用户修改 NAS 配置来绕过客户端问题。


## 用户追加：网络驱动器删除

Windows Shell 的 [FOF_WANTNUKEWARNING](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags) 要求永久删除而非回收时显示警告，并部分覆盖免确认选项。本次据此实现：普通网络共享项目每次确认永久删除；本地项目保留回收站与原确认设置；混合选择分别执行，永久删除不进入撤销栈。

不能推断所有 Windows 网络位置都没有回收站：[微软说明的文件夹重定向](https://devblogs.microsoft.com/oldnewthing/20140611-00/?p=763/) 存在网络回收站位置，NAS 服务端也可能配置自己的回收/快照策略。本客户端不检测或承诺服务端回收能力，不配置服务器回收站。拒绝访问仍按实际权限报错，不通过重试、提权或回收失败自动降级绕过。
